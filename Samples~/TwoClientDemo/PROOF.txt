OddSockets Unity SDK - Live Two-Client Round-Trip PROOF
========================================================

What this proves
----------------
Two INDEPENDENT OddSocketsClient connections were stood up against the LIVE
OddSockets platform:

  - alice : subscriber
  - bob   : publisher

bob publishes a message tagged with a random nonce; alice receives it on her
subscription. Because alice and bob are separate connections, delivery can only
have crossed the live OddSockets service - so a pass is an honest end-to-end
regression, not a local echo.

How it was run (true headless, no GUI)
--------------------------------------
  Unity 6000.0.79f1
  ODDSOCKETS_API_KEY=<live key> \
  Unity -batchmode -nographics -projectPath . \
        -runTests -testPlatform PlayMode \
        -testResults results.xml -logFile editor.log

Result
------
  NUnit result : Passed
  Duration     : 4.97s

Live trace (from editor.log)
----------------------------
  [rig] connected alice=Connected bob=Connected
  [rig] alice subscribed to rig-84485a1f
  [rig] bob published nonce=b6816e3335a54bffb41f7ab9dd8563c9
  [rig] alice RECEIVED nonce=b6816e3335a54bffb41f7ab9dd8563c9 on channel=rig-84485a1f
  [rig] round-trip received=True

SDK surface exercised end-to-end
--------------------------------
  1. Initialize         -> OddSocketsUnityConfig (api key from the environment)
  2. ConnectAsync       -> two independent authenticated connections
  3. SubscribeAsync     -> alice subscribed, acknowledged by the service
  4. PublishAsync       -> bob published from the OTHER connection
  5. message callback   -> alice received it, nonce match confirmed
  6. Disconnect         -> both clients torn down cleanly

Nothing in this run is mocked, stubbed or locally echoed: no endpoint, transport
detail or routing is configured by the sample - the SDK resolves all of it.
